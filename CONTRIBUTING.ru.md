# Руководство по внесению вклада

[English version](CONTRIBUTING.md)

Благодарим вас за интерес к участию в этом проекте! Данный репозиторий содержит вопросы и ответы с hh.ru (HeadHunter).

## Как внести вклад

### Добавление нового вопроса

1. **Создайте новую директорию** в папке `questions/` с описательным названием на английском языке в формате kebab-case (например, `mysql-performance-troubleshooting`)

2. **Создайте два файла** в директории:
   - `index.md` - английская версия
   - `index.ru.md` - русская версия

3. **Следуйте установленной структуре**:
   - Добавьте навигационные ссылки вверху (ссылка на другую языковую версию и обратно в README)
   - Укажите четкую формулировку вопроса
   - Предоставьте краткий ответ (лаконичный технический ответ)
   - Добавьте подробное объяснение с:
     - Ссылками на Википедию или официальную документацию для технических терминов
     - Примерами кода и практическими командами
     - Таблицами сравнения и чек-листами где применимо
     - Примерами из реальной практики и шагами устранения неполадок
   - Включите рекомендации по мониторингу и оповещениям где это актуально

4. **Обновите оба README файла**:
   - Добавьте новый вопрос в `README.md` (английский)
   - Добавьте новый вопрос в `README.ru.md` (русский)
   - **ВАЖНО**: Сохраняйте вопросы отсортированными в **алфавитном порядке по имени директории**, чтобы уменьшить вероятность конфликтов слияния

5. **Обеспечьте эквивалентность содержания**: Обе языковые версии должны содержать эквивалентный полный контент

### Сортировка списка вопросов

**Вопросы в файлах README должны быть отсортированы в алфавитном порядке по именам директорий.** Это критически важно для минимизации конфликтов слияния, когда несколько участников одновременно добавляют новые вопросы.

**Важно: Используйте маркированные списки (`-`), а не нумерованные (`1.`, `2.`, и т.д.) в файлах README.** Нумерованные списки всегда вызывают конфликты слияния, когда несколько участников добавляют вопросы в разные позиции. Маркированные списки решают эту проблему.

Пример правильного алфавитного порядка с маркированными списками:
```
- bash-script-review
- disk-space-inodes-issue
- iostat-disk-load-assessment
- mysql-performance-troubleshooting
- shell-script-execution-commands
```

При добавлении нового вопроса вставляйте его в правильную алфавитную позицию, а не добавляйте в конец списка.

### Рекомендации по стилю

- Используйте ясный, профессиональный язык
- Предоставляйте практические примеры с реальными командами
- Включайте ссылки на авторитетные источники (Википедия, официальная документация)
- Сохраняйте согласованность форматирования с существующими вопросами
- Используйте правильный синтаксис markdown
- Добавляйте как русскую, так и английскую версии

### Процесс создания Pull Request

1. Сделайте fork репозитория
2. Создайте feature-ветку для вашего вопроса
3. Внесите изменения, следуя указанным выше рекомендациям
4. Убедитесь, что обе языковые версии полны и эквивалентны
5. Проверьте, что вопросы отсортированы в алфавитном порядке в файлах README
6. Создайте pull request с четким описанием того, что вы добавляете
7. Укажите ссылку на связанный issue (если применимо) используя "Fixes #номер-issue"

### Сообщения коммитов

- Пишите четкие, описательные сообщения коммитов
- Используйте повелительное наклонение ("Add question about..." а не "Added question about...")
- Сохраняйте коммиты сфокусированными на одном логическом изменении

## Вопросы или проблемы?

Если у вас есть вопросы по внесению вклада или вы заметили какие-либо проблемы, пожалуйста, откройте issue на GitHub.
