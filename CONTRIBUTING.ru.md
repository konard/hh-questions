# Руководство по внесению вклада

[English version](CONTRIBUTING.md)

Благодарим вас за интерес к участию в этом проекте! Данный репозиторий содержит вопросы и ответы с hh.ru (HeadHunter).

## Как внести вклад

### Добавление нового вопроса

1. **Создайте новую директорию** в папке `questions/` с описательным названием на английском языке в формате kebab-case (например, `mysql-performance-troubleshooting`)

2. **Создайте два файла** в директории:
   - `index.md` - английская версия
   - `index.ru.md` - русская версия

3. **Следуйте установленной структуре**:
   - Добавьте навигационные ссылки вверху (ссылка на другую языковую версию и обратно в README)
   - Укажите четкую формулировку вопроса
   - Предоставьте краткий ответ (лаконичный технический ответ)
   - Добавьте подробное объяснение с:
     - Ссылками на Википедию или официальную документацию для технических терминов
     - Примерами кода и практическими командами
     - Таблицами сравнения и чек-листами где применимо
     - Примерами из реальной практики и шагами устранения неполадок
   - Включите рекомендации по мониторингу и оповещениям где это актуально

4. **Обновите оба README файла**:
   - Добавьте новый вопрос в `README.md` (английский)
   - Добавьте новый вопрос в `README.ru.md` (русский)
   - **ВАЖНО**: Сохраняйте вопросы отсортированными в **алфавитном порядке по тексту вопроса на соответствующем языке**, чтобы уменьшить вероятность конфликтов слияния и облегчить поиск вопросов для читателей

5. **Обеспечьте эквивалентность содержания**: Обе языковые версии должны содержать эквивалентный полный контент

### Сортировка списка вопросов

**Вопросы в файлах README должны быть отсортированы в алфавитном порядке по тексту вопроса на соответствующем языке.** Это критически важно для:
- Минимизации конфликтов слияния, когда несколько участников одновременно добавляют новые вопросы
- Облегчения поиска вопросов читателями на их родном языке

**Важно: Используйте маркированные списки (`-`), а не нумерованные (`1.`, `2.`, и т.д.) в файлах README.** Нумерованные списки всегда вызывают конфликты слияния, когда несколько участников добавляют вопросы в разные позиции. Маркированные списки решают эту проблему.

**Правила сортировки:**
- `README.md` (английский): Сортируйте вопросы в алфавитном порядке по английскому тексту вопроса
- `README.ru.md` (русский): Сортируйте вопросы в алфавитном порядке по русскому тексту вопроса
- Один и тот же вопрос может находиться в разных позициях в английском и русском README из-за перевода

Пример правильного алфавитного порядка с маркированными списками (русский):
```
- [Достаточно ли команды iostat -x чтобы оценить реальную нагрузку на диск?](...)
- [Какие зависимости (явные и неявные) используются в этой роли: rhel_python_sub?](...)
- [Клиент жалуется на проблемы в работе БД MySQL...](...)
- [Проведите ревью bash-скрипта](...)
- [Расскажите, каким образом вы будете блокировать в Nginx запросы вида...](...)
```

При добавлении нового вопроса вставляйте его в правильную алфавитную позицию на основе текста вопроса, а не добавляйте в конец списка.

### Работа с изображениями

**Используйте глобальный индекс изображений**, чтобы позволить переиспользование изображений в разных вопросах и создание вариаций вопросов, которые отличаются только номером изображения.

**Организация изображений:**
1. **Храните все изображения** в глобальной директории `/images/` в корне репозитория
2. **Называйте изображения** используя последовательные номера: `image-1.png`, `image-2.png`, `image-3.png` и т.д.
3. **Ссылайтесь на изображения** из вопросов используя относительные пути: `../../images/image-N.png`

**Именование вопросов с изображениями:**
- Когда вопрос использует изображение, добавьте номер изображения к названию директории: `server-monitoring-analysis-1`, `server-monitoring-analysis-2` и т.д.
- Это позволяет создавать несколько похожих вопросов, которые отличаются только используемым изображением/скриншотом
- Обновите текст вопроса в файлах README, чтобы указать, какое изображение используется: "...по скриншоту (изображение-1)..."

**Пример структуры:**
```
/images/
  image-1.png
  image-2.png
/questions/
  server-monitoring-analysis-1/
    index.md          (ссылается на ../../images/image-1.png)
    index.ru.md       (ссылается на ../../images/image-1.png)
  server-monitoring-analysis-2/
    index.md          (ссылается на ../../images/image-2.png)
    index.ru.md       (ссылается на ../../images/image-2.png)
```

**Преимущества глобального индекса изображений:**
- Уникальная нумерация для всех изображений в репозитории
- Легко ссылаться на одно и то же изображение из нескольких вопросов при необходимости
- Четкое версионирование при создании вариаций вопросов с разными скриншотами
- Организованное центральное расположение для всех визуальных ресурсов

### Рекомендации по стилю

- Используйте ясный, профессиональный язык
- Предоставляйте практические примеры с реальными командами
- Включайте ссылки на авторитетные источники (Википедия, официальная документация)
- Сохраняйте согласованность форматирования с существующими вопросами
- Используйте правильный синтаксис markdown
- Добавляйте как русскую, так и английскую версии

### Процесс создания Pull Request

1. Сделайте fork репозитория
2. Создайте feature-ветку для вашего вопроса
3. Внесите изменения, следуя указанным выше рекомендациям
4. Убедитесь, что обе языковые версии полны и эквивалентны
5. Проверьте, что вопросы отсортированы в алфавитном порядке в файлах README
6. Создайте pull request с четким описанием того, что вы добавляете
7. Укажите ссылку на связанный issue (если применимо) используя "Fixes #номер-issue"

### Сообщения коммитов

- Пишите четкие, описательные сообщения коммитов
- Используйте повелительное наклонение ("Add question about..." а не "Added question about...")
- Сохраняйте коммиты сфокусированными на одном логическом изменении

## Вопросы или проблемы?

Если у вас есть вопросы по внесению вклада или вы заметили какие-либо проблемы, пожалуйста, откройте issue на GitHub.
