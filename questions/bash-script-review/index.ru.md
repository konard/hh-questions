# Вопрос

Проведите ревью bash-скрипта:

```bash
#!/bin/bash

file=$1

if [ -f $file ]
then
echo "File exists"
else
echo "File does not exist"
fi
```

[English version](index.md) | [Все вопросы](../../README.ru.md)

---

## Краткий ответ

В скрипте есть несколько критических проблем: отсутствие кавычек вокруг переменной `$file` (ломается при пробелах/спецсимволах), непоследовательная индентация, потенциальные уязвимости безопасности при обработке путей к файлам и отсутствие проверки входных данных.

---

## Подробное объяснение

Этот [bash-скрипт](https://ru.wikipedia.org/wiki/Bash) пытается проверить существование [файла](https://ru.wikipedia.org/wiki/Компьютерный_файл), но содержит несколько проблем, которые должны быть выявлены при [ревью кода](https://ru.wikipedia.org/wiki/Инспекция_кода).

### 1. Отсутствие кавычек при раскрытии переменной

**Проблема:** Переменная `$file` используется без [кавычек](https://www.gnu.org/software/bash/manual/html_node/Quoting.html) в условии проверки.

```bash
if [ -f $file ]  # Неправильно
```

**Причина:** Если [имя файла](https://ru.wikipedia.org/wiki/Имя_файла) содержит [пробелы](https://ru.wikipedia.org/wiki/Пробел) или [спецсимволы](https://ru.wikipedia.org/wiki/Управляющие_символы), скрипт выдаст ошибку или будет вести себя непредсказуемо из-за [разбиения слов](https://www.gnu.org/software/bash/manual/html_node/Word-Splitting.html).

**Пример:**
```bash
# Если file="my document.txt", проверка становится:
[ -f my document.txt ]  # Интерпретируется как несколько аргументов
```

**Исправление:**
```bash
if [ -f "$file" ]  # Правильно - сохраняет пробелы и спецсимволы
```

### 2. Отсутствие проверки входных данных

**Проблема:** Скрипт не проверяет, был ли передан [аргумент](https://ru.wikipedia.org/wiki/Аргумент_(программирование)).

**Причина:** Если запустить скрипт без аргументов, `$file` будет пустым, и проверка будет выполнена для пустой [строки](https://ru.wikipedia.org/wiki/Строка_(программирование)), что может привести к запутанным результатам.

**Исправление:**
```bash
if [ -z "$1" ]; then
    echo "Использование: $0 <имя_файла>" >&2
    exit 1
fi
```

### 3. Непоследовательная индентация

**Проблема:** Команды `echo` внутри блока [if-else](https://ru.wikipedia.org/wiki/Условный_оператор_(программирование)) не имеют отступов.

**Влияние:** Хотя функционально код корректен, плохое [форматирование кода](https://ru.wikipedia.org/wiki/Стиль_программирования) снижает [читаемость](https://ru.wikipedia.org/wiki/Читаемость) и поддерживаемость.

**Исправление:**
```bash
if [ -f "$file" ]; then
    echo "File exists"
else
    echo "File does not exist"
fi
```

### 4. Рекомендации по современному синтаксису

**Текущий вариант:** Использует старый синтаксис проверки `[ ]` и многострочный формат `if-then`.

**Лучшие альтернативы:**

Использование `[[ ]]` (более надежно):
```bash
if [[ -f "$file" ]]; then
    echo "File exists"
else
    echo "File does not exist"
fi
```

**Преимущества `[[ ]]`:**
- Нет [разбиения слов](https://www.gnu.org/software/bash/manual/html_node/Word-Splitting.html) или [раскрытия шаблонов](https://www.gnu.org/software/bash/manual/html_node/Filename-Expansion.html)
- Поддержка дополнительных операторов (`&&`, `||`, `=~`)
- Более читаемый и последовательный

### 5. Вопросы безопасности

**Проблема:** Отсутствует проверка того, что `$file` является безопасным [путем](https://ru.wikipedia.org/wiki/Путь_к_файлу).

**Потенциальные риски:**
- Атаки [обхода пути](https://ru.wikipedia.org/wiki/Обход_каталога) (например, `../../etc/passwd`)
- Доступ к файлам вне предполагаемой директории
- Переход по [символическим ссылкам](https://ru.wikipedia.org/wiki/Символическая_ссылка) к конфиденциальным местам

**Дополнительные проверки для рассмотрения:**
```bash
# Преобразовать в абсолютный путь и проверить
file=$(realpath -s "$1" 2>/dev/null) || {
    echo "Неверный путь к файлу" >&2
    exit 1
}
```

### 6. Направление сообщений об ошибках

**Проблема:** Сообщения об ошибках выводятся в [стандартный вывод](https://ru.wikipedia.org/wiki/Стандартные_потоки#Стандартный_вывод) вместо [стандартного потока ошибок](https://ru.wikipedia.org/wiki/Стандартные_потоки#Стандартный_поток_ошибок).

**Исправление:**
```bash
echo "File does not exist" >&2
```

### Улучшенная версия

Вот исправленная версия, учитывающая все проблемы:

```bash
#!/bin/bash

# Проверка входных данных
if [ -z "$1" ]; then
    echo "Использование: $0 <имя_файла>" >&2
    exit 1
fi

file="$1"

# Проверка существования файла
if [[ -f "$file" ]]; then
    echo "File exists"
else
    echo "File does not exist" >&2
    exit 1
fi
```

### Сводка проблем

| Проблема | Критичность | Влияние |
|----------|-------------|---------|
| Отсутствие кавычек вокруг `$file` | Высокая | Скрипт ломается при пробелах/спецсимволах |
| Отсутствие проверки входных данных | Средняя | Запутанное поведение без аргументов |
| Непоследовательная индентация | Низкая | Снижена читаемость |
| Старый синтаксис проверки | Низкая | Менее надежно, чем современные альтернативы |
| Вопросы безопасности | Средняя | Потенциальный несанкционированный доступ |
| Направление вывода ошибок | Низкая | Неправильная обработка ошибок |

### Лучшие практики для bash-скриптов

1. **Всегда заключайте переменные в кавычки**, если только вам не нужно специально разбиение слов
2. **Проверяйте все входные данные** перед их использованием
3. **Используйте последовательную индентацию** (обычно 2 или 4 пробела)
4. **Предпочитайте `[[ ]]` вместо `[ ]`** в bash-скриптах
5. **Отправляйте ошибки в stderr** с помощью `>&2`
6. **Используйте `set -euo pipefail`** для лучшей обработки ошибок
7. **Добавляйте осмысленные [коды возврата](https://ru.wikipedia.org/wiki/Код_возврата)**
