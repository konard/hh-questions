# Вопрос

Что происходит на сервере (см. скриншот мониторинга)? Опишите в формате ответа для клиента, если у вас есть предложения по оптимизации, также укажите их.

[English version](index.md) | [Все вопросы](../../README.ru.md)

---

## Краткий ответ

Сервер испытывает критическую нагрузку: высокий Load Average (33.00), активное использование swap-памяти (7.4G), повышенная дисковая активность с I/O wait, множество Apache-процессов. Необходима оптимизация памяти, настройка Apache, анализ дисковой подсистемы и возможное масштабирование ресурсов.

## Подробное объяснение

На основе анализа [скриншота мониторинга сервера](https://ru.wikipedia.org/wiki/Мониторинг_компьютерных_систем) (вывод [htop](https://ru.wikipedia.org/wiki/Htop)/[top](https://ru.wikipedia.org/wiki/Top) и [iostat](https://en.wikipedia.org/wiki/Iostat)) можно выявить несколько критических проблем с [производительностью](https://ru.wikipedia.org/wiki/Производительность_компьютерной_системы).

### Анализ текущего состояния сервера

#### 1. Критически высокий Load Average

**Наблюдение:** Load Average составляет **33.00**, что указывает на серьезную перегрузку системы.

**Что это означает:**
- [Load Average](https://ru.wikipedia.org/wiki/Load_average) показывает среднее количество процессов, ожидающих выполнения на [CPU](https://ru.wikipedia.org/wiki/Центральный_процессор) или находящихся в состоянии [I/O wait](https://ru.wikipedia.org/wiki/Ввод-вывод)
- Значение 33.00 при видимом количестве [процессорных ядер](https://ru.wikipedia.org/wiki/Многоядерный_процессор) означает значительную очередь на выполнение
- Это указывает на то, что система не справляется с текущей нагрузкой

**Причины:**
- Недостаточные вычислительные ресурсы
- Блокировки на дисковых операциях
- Слишком много одновременных процессов

#### 2. Активное использование swap-памяти

**Наблюдение:** Swap: **7.4G** используется, что является критическим показателем.

**Что это означает:**
- [Оперативная память (RAM)](https://ru.wikipedia.org/wiki/Оперативная_память) исчерпана
- Система использует [файл подкачки (swap)](https://ru.wikipedia.org/wiki/Подкачка_страниц) на диске
- Memory: около 676.5M свободной памяти из общего объема

**Влияние:**
- Swap значительно медленнее RAM (в 100-1000 раз)
- Это вызывает замедление работы всех приложений
- Увеличивается нагрузка на [дисковую подсистему](https://ru.wikipedia.org/wiki/Дисковый_массив)

**Критичность:** ВЫСОКАЯ - это одна из основных причин деградации производительности

#### 3. Множество Apache-процессов

**Наблюдение:** В списке процессов видны многочисленные процессы [Apache](https://ru.wikipedia.org/wiki/Apache_HTTP_Server) в различных состояниях.

**Проблемы:**
- Каждый Apache-процесс потребляет [память](https://ru.wikipedia.org/wiki/Оперативная_память)
- Слишком много параллельных процессов усугубляет нехватку RAM
- Часть процессов находится в состоянии ожидания

**Возможные причины:**
- Неоптимальная конфигурация Apache ([MaxClients](https://httpd.apache.org/docs/2.4/mod/mpm_common.html#maxrequestworkers), [MaxRequestWorkers](https://httpd.apache.org/docs/2.4/mod/mpm_common.html#maxrequestworkers))
- [DDoS-атака](https://ru.wikipedia.org/wiki/DDoS) или всплеск трафика
- Медленные [PHP](https://ru.wikipedia.org/wiki/PHP)-скрипты, удерживающие процессы

#### 4. Повышенная дисковая активность

**Наблюдение:** В выводе видна высокая активность дисковых операций (процессы с состоянием I/O).

**Индикаторы:**
- Процессы в состоянии `dirty` (ожидание записи на диск)
- Множество операций чтения/записи
- Возможные высокие значения I/O wait

**Причины:**
- Использование swap увеличивает дисковую активность
- [Фрагментация файловой системы](https://ru.wikipedia.org/wiki/Фрагментация_(компьютер))
- Медленные диски ([HDD](https://ru.wikipedia.org/wiki/Жёсткий_диск) вместо [SSD](https://ru.wikipedia.org/wiki/Твердотельный_накопитель))
- Большой объем логирования

#### 5. Процессы cron

**Наблюдение:** Видны множественные процессы `cron003` и подобные в состоянии `idle` или `apache`.

**Анализ:**
- Множество [cron-задач](https://ru.wikipedia.org/wiki/Cron) может усугублять нагрузку
- Некоторые задачи могут выполняться одновременно
- Необходимо проверить расписание выполнения

## Ответ для клиента

### Уважаемый клиент,

На основе анализа мониторинга вашего сервера выявлены следующие проблемы:

#### Текущая ситуация

1. **Критическая нехватка оперативной памяти**
   - Сервер активно использует swap-память (7.4 GB), что замедляет работу всех приложений в 100-1000 раз
   - Свободной RAM осталось менее 700 MB

2. **Перегрузка системы**
   - Load Average составляет 33.00, что говорит о том, что сервер не справляется с текущей нагрузкой
   - В очереди на выполнение находится большое количество процессов

3. **Избыточное количество веб-сервер процессов**
   - Apache запустил слишком много рабочих процессов, что усиливает нехватку памяти
   - Каждый процесс удерживает ресурсы памяти

4. **Повышенная нагрузка на дисковую подсистему**
   - Из-за использования swap увеличилась дисковая активность
   - Это создает дополнительные задержки при обработке запросов

### Рекомендации по оптимизации

#### Срочные меры (применить немедленно)

**1. Увеличение оперативной памяти**
- **Рекомендация:** Добавить минимум 8-16 GB RAM
- **Обоснование:** Это устранит использование swap и значительно ускорит работу
- **Приоритет:** КРИТИЧЕСКИЙ

**2. Оптимизация конфигурации Apache**

Необходимо ограничить количество одновременных процессов Apache. В файле конфигурации ([httpd.conf](https://httpd.apache.org/docs/2.4/configuring.html) или [apache2.conf](https://httpd.apache.org/docs/2.4/configuring.html)):

```apache
# Для MPM Prefork
<IfModule mpm_prefork_module>
    StartServers          5
    MinSpareServers       5
    MaxSpareServers      10
    MaxRequestWorkers    50  # Уменьшить с текущего значения
    MaxConnectionsPerChild 3000
</IfModule>

# Для MPM Worker/Event (более эффективно)
<IfModule mpm_event_module>
    StartServers          2
    MinSpareThreads      25
    MaxSpareThreads      75
    ThreadsPerChild      25
    MaxRequestWorkers    50  # Рассчитать: (RAM * 0.8) / avg_process_size
    MaxConnectionsPerChild 3000
</IfModule>
```

**Расчет MaxRequestWorkers:**
```
MaxRequestWorkers = (Доступная RAM в MB * 0.8) / Средний размер процесса Apache
```

Например, при 4 GB RAM и среднем размере процесса 50 MB:
```
MaxRequestWorkers = (4096 * 0.8) / 50 ≈ 65
```

**3. Отключение или уменьшение swap**

```bash
# Временно уменьшить приоритет swap
sudo sysctl vm.swappiness=10

# Сделать изменение постоянным
echo "vm.swappiness=10" | sudo tee -a /etc/sysctl.conf
```

**Объяснение:** [Swappiness](https://ru.wikipedia.org/wiki/Подкачка_страниц) контролирует, насколько агрессивно система использует swap. Значение 10 минимизирует swap, сохраняя его только для экстренных случаев.

**4. Перезапуск Apache для освобождения памяти**

```bash
# Graceful restart для применения новой конфигурации
sudo systemctl reload apache2
# или
sudo apachectl graceful
```

#### Среднесрочные меры (1-2 недели)

**5. Переход на более эффективный веб-сервер**

Рассмотрите использование [Nginx](https://ru.wikipedia.org/wiki/Nginx) в качестве [обратного прокси](https://ru.wikipedia.org/wiki/Обратный_прокси) перед Apache или полный переход на Nginx + [PHP-FPM](https://www.php.net/manual/ru/install.fpm.php):

**Преимущества:**
- Nginx потребляет в 5-10 раз меньше памяти
- Лучше обрабатывает статический контент
- Эффективнее работает с большим количеством соединений

**Архитектура:**
```
Клиент → Nginx (статика + прокси) → PHP-FPM (динамический контент)
```

**6. Оптимизация PHP-приложений**

```bash
# Включить OPcache для PHP
# В php.ini:
opcache.enable=1
opcache.memory_consumption=128
opcache.max_accelerated_files=10000
opcache.revalidate_freq=60
```

**7. Внедрение кэширования**

- **[Redis](https://ru.wikipedia.org/wiki/Redis)** или **[Memcached](https://ru.wikipedia.org/wiki/Memcached)** для кэширования данных приложений
- **[Varnish](https://ru.wikipedia.org/wiki/Varnish)** для HTTP-кэширования
- Кэширование на уровне приложения (страницы, запросы к БД)

**8. Анализ и оптимизация cron-задач**

```bash
# Проверить все cron-задачи
sudo crontab -l
ls -la /etc/cron.*

# Распределить задачи во времени, избегая одновременного запуска
# Добавить логирование для анализа времени выполнения
```

**9. Оптимизация дисковой подсистемы**

- **Переход на SSD:** Если используются HDD, миграция на SSD даст прирост в 10-100 раз
- **Настройка файловой системы:** Использование [ext4](https://ru.wikipedia.org/wiki/Ext4) с опцией `noatime`
- **Вынос логов:** Перенести логи на отдельный диск или ограничить их размер

```bash
# В /etc/fstab добавить noatime для уменьшения операций записи
/dev/sda1  /  ext4  defaults,noatime  0  1
```

#### Долгосрочные меры (планирование)

**10. Масштабирование инфраструктуры**

**Вертикальное масштабирование:**
- Увеличение RAM до 16-32 GB
- Добавление CPU-ядер
- Использование SSD NVMe

**Горизонтальное масштабирование:**
- [Балансировщик нагрузки](https://ru.wikipedia.org/wiki/Балансировка_нагрузки) + несколько веб-серверов
- Отдельный сервер для [базы данных](https://ru.wikipedia.org/wiki/База_данных)
- [CDN](https://ru.wikipedia.org/wiki/Content_Delivery_Network) для статического контента

**11. Мониторинг и алертинг**

Внедрение системы мониторинга для предотвращения подобных ситуаций:

- **[Prometheus](https://ru.wikipedia.org/wiki/Prometheus_(программное_обеспечение)) + [Grafana](https://ru.wikipedia.org/wiki/Grafana)**: визуализация метрик
- **[Zabbix](https://ru.wikipedia.org/wiki/Zabbix)** или **[Nagios](https://ru.wikipedia.org/wiki/Nagios)**: комплексный мониторинг
- Настройка алертов на критические метрики:
  - Load Average > 10
  - Swap usage > 1 GB
  - Free RAM < 500 MB
  - Disk I/O wait > 30%

**12. Регулярный аудит производительности**

```bash
# Еженедельный анализ
- Проверка логов Apache на медленные запросы
- Анализ использования ресурсов по времени суток
- Выявление тяжелых процессов
- Проверка обновлений ПО
```

## Полезные команды для диагностики

### Проверка использования памяти

```bash
# Общая информация о памяти
free -h

# Процессы, использующие больше всего памяти
ps aux --sort=-%mem | head -10

# Подробная информация о памяти
cat /proc/meminfo

# Проверка swap
swapon -s
```

### Анализ Apache

```bash
# Количество Apache-процессов
ps aux | grep apache2 | wc -l

# Средний размер процесса Apache
ps aux | grep apache2 | awk '{sum+=$6} END {print sum/NR/1024 " MB"}'

# Текущая конфигурация MPM
apachectl -V | grep -i mpm

# Статус Apache
apachectl status
```

### Мониторинг в реальном времени

```bash
# Интерактивный мониторинг процессов
htop

# Мониторинг дисковой активности
iostat -x 2

# Мониторинг использования swap
vmstat 2

# Анализ I/O по процессам (требует root)
sudo iotop
```

### Проверка системной нагрузки

```bash
# Load average и uptime
uptime

# Детальная информация о CPU
mpstat 1 5

# Проверка наиболее нагруженных процессов
top -b -n 1 | head -20
```

## Ожидаемые результаты после оптимизации

После применения рекомендованных мер вы заметите:

1. **Значительное ускорение работы сайта** - в 5-10 раз после добавления RAM и отключения swap
2. **Стабильность работы** - Load Average снизится до приемлемых значений (< 5)
3. **Быстрый отклик** - уменьшение времени ответа сервера
4. **Масштабируемость** - возможность обработки большего количества одновременных посетителей
5. **Предсказуемость** - с системой мониторинга вы будете заранее знать о проблемах
